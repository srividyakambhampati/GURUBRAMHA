GuruBramha Platform
Comprehensive Database Schema & Architecture Documentation
1. Database Overview
Database Name:
GuruBramha DB
Purpose:
To securely manage and persist all platform data including user identities, elite course content, practice arena challenges, interview preparation roadmaps, transaction histories, and verified documents.
Technologies Used:
MongoDB (NoSQL Database), Mongoose (Node.js ODM)
Connection Structure:
The application connects to a MongoDB cluster using a secure connection string defined in the environment variables. The connection is established globally via the Mongoose driver.
2. Complete Collections Structure
2.1 Users Collection
Stores user identities, academic profiles, external portfolio links, and subscription details.
_id (ObjectId) — Primary Key
firebaseUid (String) — Required, Unique — Used for authentication sync.
displayName (String) — Required — Full name of the user.
email (String) — Required, Unique
phone, gender, college, branch, district, state (String) — Optional — Demographic and academic details.
age (Number) — Optional
githubUrl, leetcodeUrl, codechefUrl (String) — Optional — Professional links.
isSubscribed (Boolean) — Default: false — Premium access flag.
scholarPoints, currentStreak (Number) — Default: 0 — Practice arena statistics.
solvedProblems (Array of ObjectIds) — References the Problems Collection.
bookmarkedCompanies (Array of ObjectIds) — References the Companies Collection.
2.2 Courses Collection
Stores details for the elite course library and curriculum.
_id (ObjectId) — Primary Key
title, instructor, category (String) — Required
level (String) — Required — Enum: Beginner, Intermediate, Advanced.
price (Number) — Required
rating, reviewsCount, studentsEnrolled (Number) — Default: 0
lessons (Array of Objects) — Contains title, duration, videoUrl, and isFreePreview flag.
2.3 Problems Collection
Stores coding challenges for the Elite Practice Arena.
_id (ObjectId) — Primary Key
title, category, description (String) — Required
difficulty (String) — Required — Enum: Easy, Medium, Hard.
accuracy (Number) — Default: 0
points (Number) — Default: 100
validationCases (Array of Objects) — Contains input, output, and isHidden flag.
2.4 Companies Collection
Stores interview preparation roadmaps and placement protocols.
_id (ObjectId) — Primary Key
name (String) — Required
type (String) — Required — Enum: Product Based, Service Based, Startup.
skills, process (Array of Strings)
rounds (Array of Objects) — Details the technical and HR rounds.
roadmap30Days (Array of Objects) — Details week-by-week focus points.
2.5 Transactions Collection
Stores Razorpay payment and subscription details.
_id (ObjectId) — Primary Key
user (ObjectId) — Required, Foreign Key — Links to the Users collection.
amount (Number) — Required
razorpayOrderId (String) — Required, Indexed
status (String) — Enum: created, successful, failed (Default: created).
2.6 Documents Collection
Stores metadata for certificates fetched via DigiLocker.
_id (ObjectId) — Primary Key
user (ObjectId) — Required, Foreign Key — Links to the Users collection.
digilockerId, name, uri (String) — Required
3. User Side Database Structure
From the user's perspective, the database structure facilitates the following interactions:
Authentication/Login: Managed via Firebase on the frontend, which syncs with the users collection using the unique firebaseUid.
Profile Data: Users can update their academic history, age, gender, and social links (GitHub, LeetCode) directly into the users table.
Courses & Subscriptions: Users browse the courses collection. Initiating a purchase creates a transaction document. Upon success via Razorpay, the user's isSubscribed flag is set to true granting access to premium content.
Practice/Coding: Users query the problems collection. Successful submissions append the Problem ID to the user's solvedProblems array and increase their scholarPoints.
4. Admin Side Database Structure
The admin perspective provides full control over the platform's content and tracking:
User Management: Admins can query the users collection to monitor scholar points, view academic demographics, or manually revoke/grant subscriptions.
Content Management: Admins have complete access to courses, problems, and companies. They can add new coding challenges, update curriculum videos, and add new interview roadmaps.
Analytics: Aggregating user solved problems, course enrollments, and problem accuracy helps admins track platform engagement and revenue.
5. API & Backend Mapping
Profile Endpoints:
/api/users/profile maps to User collection lookups and updates.
Course Endpoints:
/api/courses maps to Course collection. Protected endpoints verify the User's subscription status.
Payment Endpoints:
/api/payment/order and /api/payment/verify interact securely with Razorpay and the Transactions collection.
DigiLocker Endpoints:
/api/digilocker handles OAuth flows and stores successful document links into the Documents collection.
6. Deployment Readiness
Environment Configuration: The server requires specific environment variables including MONGODB_URI, RAZORPAY_KEY_ID, RAZORPAY_KEY_SECRET, and DigiLocker credentials.
Security Measures: Mongoose enforces strict schema validation (Required fields, Enums, Number formats) preventing malformed data entry. Implicit indexes ensure rapid querying across massive datasets. Network access to the MongoDB cluster should be strictly IP-restricted for production environments.
